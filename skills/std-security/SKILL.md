# std-security — безопасность

Источник ИТС (сессия): [#std678 Безопасность прикладного API сервера](https://its.1c.ru/db/v8std/content/678/hdoc)  
Раздел: [Общие вопросы безопасности](https://its.1c.ru/db/v8std/browse/13/-1/36).  
Связано: #std679 (`std-code-style`), ограничение внешнего кода (статьи раздела).

## Контекст угрозы (#std678)

Тонкий/веб-клиент ходит на сервер по открытому HTTP. Сторонний код может вызывать сервер так же, как штатный клиент.

## 1. Поверхность серверного API

Потенциально опасны:

- экспортные процедуры/функции общих модулей с **«Сервер» + «Вызов сервера»** (прямой вызов с клиента);
- **любые** процедуры/функции модуля формы с `&НаСервере` / `&НаСервереБезКонтекста` — их можно вызвать из клиентского контекста формы даже **без** `Экспорт` после `ПолучитьФорму`.

Пример угрозы: проверка на клиенте + серверная `ЗарегистрироватьУвольнение()` — злоумышленник зовёт серверную напрямую и обходит проверку.

### Must

1. Не клади бизнес-логику в серверные процедуры модуля формы, если она не про UI/реквизиты формы — выноси в серверные общие модули / модуль объекта (#std678 п.1.2).
2. «Вызов сервера» — только узкий безопасный API (#std679): только разрешённые пользователю действия и данные.
3. Особо осторожно с **привилегированным** режимом и модулями `ПолныеПрава`.
4. На клиент возвращай **окончательный** результат расчёта; не отдавай исходные/промежуточные данные, раскрывающие приватную логику (#std678 п.3). Клиентские данные не считаются защищёнными.

## 2. Внешний / динамический код

Опасно на сервере:

- выполнение «внешнего» кода и произвольных текстов запросов не из прикладного решения;
- внешние отчёты/обработки, COM, внешние компоненты (могут звать модули **без** «Вызов сервера», объекты, привилегированный режим).

Это прямо угрожает данным и стабильности сервера. См. статьи раздела про ограничение внешнего кода / `Выполнить` / `Вычислить`.

## Must not

- Толстый экспорт «на всякий случай» в `…ВызовСервера`
- Критичные проверки только на клиенте при наличии серверной процедуры «рядом»
- Секреты в коде / ЖР / сообщениях пользователю
- `Выполнить`/`Вычислить` и произвольные запросы от пользователя без жёсткого контроля

## Чеклист

- [ ] API `ВызовСервера` минимален и безопасен по правам
- [ ] Нет важной бизнес-логики только в `&НаСервере` модуля формы
- [ ] Нет обходимых клиентских проверок перед серверным действием
- [ ] На клиент не уходят лишние/промежуточные данные
- [ ] Нет необоснованного внешнего/динамического кода на сервере
