# std-client-server — клиент-сервер

Источник ИТС (сессия): [#std487 Минимизация серверных вызовов и трафика](https://its.1c.ru/db/v8std/content/487/hdoc)  
Раздел: [Клиент-серверное взаимодействие](https://its.1c.ru/db/v8std/browse/13/-1/35).  
Связано: #std679 (`std-code-style` / `std-security`), #std680.

## Принцип (#std487 п.1)

На **каждое** действие пользователя конфигурация **не должна** добавлять лишние серверные вызовы сверх того, что делает платформа. Исключения — только с обоснованием.

Для медленного канала и мобильного клиента оптимизируй ещё и **трафик**; отлаживай с имитацией задержек.

## Запуск приложения

- В `ПередНачаломРаботыСистемы` / `ПриНачалеРаботыСистемы` по умолчанию **без** серверных вызовов.
- Нужны данные? **Один** вызов, отдающий все параметры запуска; лучше модуль с **повторным использованием** (`ПараметрыРаботыКлиента` и т.п.).
- С БСП: `ОбщегоНазначенияПереопределяемый.ПриДобавленииПараметровРаботыКлиента…` + `СтандартныеПодсистемыКлиент.ПараметрыРаботыКлиента…`.

## Периодические вызовы

- Объединяй в один; период по возможности **не чаще ~20 минут**.
- Предпочитай **уведомления клиента** (сервер → клиент), а не опрос.
- На начальной странице периодику не люби; кнопка «Обновить»; если нужна — выкл. по умолчанию, период ≥ 1 мин.
- БСП: длительные операции / серверные оповещения / периодическая отправка данных клиента — через штатные переопределяемые процедуры.

## Открытие и команды формы

1. Открывай форму **одним** `ОткрытьФорму` (+ параметры).
2. **Запрещено** ходить на сервер из клиентских `ПриОткрытии` / `ПриПовторномОткрытии`. Данные — в `ПриСозданииНаСервере` (реквизиты формы).
3. Не дергай `…ПовтИсп` при открытии «впрок» — первый вызов всё равно ударит по серверу.
4. Несколько `ПодключитьОбработчикОжидания` → один обработчик / одно фоновое (БСП `ДлительныеОперацииКлиент`).
5. Локальная команда формы → **≤ 1** серверный вызов; клиентские проверки — на заранее подготовленных реквизитах.
6. Выбор из справочника → в общем случае один вызов через `ОткрытьФорму` (+ опционально ещё один на серверную бизнес-логику после выбора).
7. Глобальная команда → один серверный вызов; отчёт — без доп. вызовов; формируй через `СформироватьПриОткрытии`, не из `ПриОткрытии`.

## Подбор / большие списки

Не таскай большие `ДанныеФормыКоллекция` параметром формы (дочитывание). Используй **временное хранилище** на сервере: ≤ ~2 вызова на открытие и ≤ ~2 на закрытие; очищай/`Переиспользовать` хранилище (жизнь формы).

## Запись формы

Не дёргай сервер из клиентских `ПередЗаписью`/`ПослеЗаписи` — логика в `…НаСервере` + `ПараметрыЗаписи` / реквизиты.

## Передача данных

- Не передавай лишнее; предпочитай `&НаСервереБезКонтекста` с нужным значением вместо контекстного вызова «ради одного реквизита».
- Параметры серверных процедур/функций, зовущихся с клиента: префикс **`Знач`** — не гонять значение обратно.
- Возвращай с сервера **результат**, не эхо входных параметров.
- Не размножай неявные серверные свойства/методы платформы с клиента (`ПолучитьИзВременногоХранилища`, свойства поля формы и т.д.) — собери в один вызов.

## Чеклист

- [ ] Нет сервера из `ПриОткрытии` / `ПриПовторномОткрытии`
- [ ] Команда формы ≤ 1 серверный вызов
- [ ] Параметры с `Знач`; возврат только нужного
- [ ] Большие списки — через временное хранилище
- [ ] Периодика редкая / через оповещения
