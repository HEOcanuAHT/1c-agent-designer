# std-transactions-locks — транзакции и модификация данных

Практика порядка блокировок / диагностики — [docs/practices.md](docs/practices.md) (адапт. ai_rules_1c).

Источник ИТС (сессия): [#std783 Транзакции](https://its.1c.ru/db/v8std/content/783/hdoc)  
Раздел: [Обработка и модификация данных](https://its.1c.ru/db/v8std/browse/13/-1/26/29).

## Особенности платформы (#std783)

- Вложенные транзакции как независимые не работают.
- Исключение **не** отменяет транзакцию сразу, но запрещает успешную фиксацию — даже если исключение поймали.
- Платформа сама открывает транзакцию при любой записи в БД.

Нарушения → ошибки вида «В этой транзакции уже происходили ошибки».

## Must

1. Каждому `НачатьТранзакцию` — парный `ЗафиксироватьТранзакцию` / `ОтменитьТранзакцию`.
2. Начало и фиксация/отмена — **в одном методе**.
3. Паттерн:

```bsl
НачатьТранзакцию(); // вне Попытки, сразу перед ней
Попытка
    // блокировка, чтение, запись — всё здесь
    ЗафиксироватьТранзакцию(); // последним в Попытке
Исключение
    ОтменитьТранзакцию(); // сначала
    // журнал регистрации
    ВызватьИсключение; // если есть внешняя транзакция
КонецПопытки;
```

4. Не открывай явную транзакцию «на пустом месте», если делаешь только запись нового объекта без ответственного чтения — платформа откроет сама.
5. Не держи длинные транзакции; для больших загрузок — порции (ориентир ИТС: порция ≤ ~20 сек в нагруженной системе — таймаут блокировки по умолчанию).
6. В сбойной активной транзакции не ходи в БД (даже за представлением ссылки).

## Прочее из раздела ИТС

Управляемые блокировки, блокировка объекта для редактирования, ответственное чтение, чтение отдельных реквизитов, многократная запись регистров — по статьям раздела.

## Чеклист

- [ ] Пара `Начать`/`Зафиксировать|Отменить` в одном методе
- [ ] В `Исключение` сначала `ОтменитьТранзакцию`
- [ ] Нет лишней явной транзакции на простой записи нового объекта
- [ ] Длинные операции разбиты на порции
